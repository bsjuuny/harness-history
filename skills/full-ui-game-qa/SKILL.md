# Full UI game QA

게임·교육 콘텐츠의 “전체 검수”를 화면 일부나 템플릿 시안 검사로 축소하지 않는다. 프로젝트별 `AGENTS.md`와 출시 계약이 이 절차보다 우선한다.

## 1. 범위를 먼저 고정한다

1. 운영에 노출되는 게임·레벨·단계를 코드나 카탈로그에서 목록화한다.
2. 각 항목에 `진입`, `첫 안내`, `첫 행동`, `오답`, `정답`, `단계 전환`, `최종 완료`, `다시 하기/목록` 상태를 붙인다.
3. 화면 크기 행에는 최소한 프로젝트가 지원하는 휴대폰 세로·가로, 태블릿 세로·가로, PC, TV를 둔다.
4. 검사 수의 분모를 먼저 기록한다. 일부 표본만 봤다면 “전체”가 아니라 표본 범위를 이름으로 보고한다.

## 2. 템플릿과 실제 게임을 분리해 검사한다

- 템플릿 갤러리·스토리북·디자인 시안은 계약 참고 화면이다.
- 실제 운영 엔트리에서 같은 템플릿 ID, 구조, 자산, 조작 흐름이 적용됐는지 별도로 검사한다.
- 템플릿 자동검사 통과를 실제 게임 적용 증거로 대신하지 않는다.
- 개발 픽스처가 경로 오류나 권한 문제를 숨기지 않는지 확인한다.

## 3. 아이의 한 라운드를 끝까지 따라간다

각 대표 게임을 실제 조작으로 실행한다.

1. 글을 읽지 않아도 첫 행동을 짐작할 수 있는 큰 그림 단서가 있는지 본다.
2. 잘못 누른 뒤 안전하게 다시 시도할 수 있는지 확인한다.
3. 올바른 선택 직후 단계 TTS가 시작되는지 확인한다.
4. 단계 TTS가 끝나기 전에는 `다음`, `마치기`, 축하 화면이 나타나지 않아야 한다.
5. 설정된 문장·제목 뒤 쉼이 적용되고 TTS 종료 콜백 뒤에만 다음 행동을 연다.
6. 마지막 단계도 `선택 → 결과 TTS → 완료 화면` 순서인지 확인한다.
7. 완료 화면에는 아이가 만든 결과와 프로젝트의 승인된 축하 문구가 함께 보이는지 확인한다.

가짜 음성 종료 이벤트를 사용한 브라우저 검사는 순서 계약의 증거다. 실제 기기 음색·속도·가청 품질 증거로 보고하지 않는다.

## 4. 비주얼 자산을 장면 단위로 검사한다

- 캐릭터만 교체하고 소품·배경·아이콘·운영체제 이모지가 다른 화풍으로 남지 않았는지 확인한다.
- 캐릭터, 들고 있는 물건, 목표물, 선택 후 결과물, 완료 미리보기를 한 자산 계열로 묶어 검사한다.
- 합성 장면은 배경·캐릭터·소품을 각각 목록화한다. 캐릭터만 새 원화이고 배경이나 소품이 구형 `data:image/svg+xml`, 인라인 SVG, 운영체제 이모지로 남은 경우 장면 전체를 실패로 판정한다.
- 초기 카드뿐 아니라 드래그 후 슬롯, 정답/오답 결과, 저장된 작품 미리보기에도 같은 배경·소품 합성이 유지되는지 확인한다.
- 학습 판독을 위한 도형·숫자·선화는 의도적으로 다른 표현을 유지할 수 있으나 그 이유를 기록한다.
- 모든 필수 이미지에 대해 DOM 존재, 로드 완료, `naturalWidth > 0`, 대체 문자/이모지 부재를 자동 검사한다.
- PNG 알파가 투명해도 이미지의 버튼·카드 컨테이너가 불필요한 흰 사각 배경이나 테두리를 만들 수 있다. 최종 합성 화면의 `background-color`, `border-color`와 캡처를 함께 검사한다.
- 자동 로드·지오메트리 통과 뒤에도 캡처를 사람이 직접 보고 크기, 겹침, 이질감, 중심 정렬, 여백을 판정한다.
- 자동 검사가 통과해도 캡처에서 문장이나 그림이 고정 하단 영역 뒤로 잘리면 통과를 취소하고 수정 후 다시 렌더링한다.

## 5. 조작 크기와 화면 잘림을 수치로 확인한다

- 프로젝트의 아이용 최소 조작 크기를 실제 경계 상자로 측정한다. CSS 선언값만 보지 않는다.
- 가로 넘침, 세로 첫 화면 가림, 고정 하단 버튼, 스크롤 가능 여부, 완료 버튼 노출을 각 화면 크기에서 기록한다.
- 화면마다 가장 작은 조작 요소의 클래스·라벨·실측 크기를 실패 증거에 포함한다.
- 자동 스크린샷은 첫 화면과 완료 화면을 모두 남기고, 파일명에 화면 크기와 게임 ID를 넣는다.
- 긴 보호자·설정 모달은 열릴 때 `scrollTop=0`인지, 스크롤 뒤에도 닫기가 화면 안에 고정되는지, 하단 관리 버튼이 최소 성인 터치 크기(프로젝트 기준이 없으면 48px)를 만족하는지 확인한다.
- 닫기·완료·초기화·진단·이용권 같은 보호자 버튼은 존재와 크기만 보지 말고 실제 클릭 결과를 검사한다. 초기화는 취소 시 불변, 확인 시 초기화, 이용권은 앱 전용 목적지 요청과 실제 기기 렌더링 경계를 구분한다.

## 6. 기존 지적과 회귀를 함께 닫는다

1. 과거 QA/QC 보고서, 알려진 문제, 사용자 지적을 현재 체크리스트에 병합한다.
2. 새 수정만 검사하지 말고 이전 지적의 재발 여부를 회귀로 실행한다.
3. 테스트를 추가·수정했다면 프로젝트의 테스트 원장에도 목적, 범위, 실행 결과를 기록한다.
4. 실패한 검사와 아직 실행하지 않은 검사를 통과로 합산하지 않는다.

## 7. 전달 경계를 분리한다

최종 보고에서 다음을 별도 상태로 쓴다.

- 소스 수정
- 로컬 단위·브라우저 QA
- 캡처 시각 QC
- 패키지 생성과 무결성
- 서명
- 서버 업로드
- 라이브 URL/원격 해시 검증
- 실제 기기와 실제 아동 관찰

로컬 통과만으로 APK, 서버, 라이브 반영을 완료했다고 말하지 않는다. 이전 패키지가 소스 수정 뒤 낡았다면 명시적으로 최신본 판정에서 제외한다.

## 완료 조건

- 선언한 범위표의 모든 항목에 통과, 실패, 미실행 중 하나가 있다.
- 실제 운영 게임의 조작 여정과 다기기 캡처가 있다.
- TTS 단계·최종 완료 순서가 자동 검사로 고정돼 있다.
- 필수 자산 로드와 장면 전체 화풍을 모두 확인했다.
- 이전 지적의 재발 여부와 배포 경계가 문서에 남아 있다.
