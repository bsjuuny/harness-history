# AI 도구 출력에 비밀값을 찍지 말 것

AI 코딩 도구(Claude Code, Codex, Grok 등)는 터미널·파일 읽기 결과를 모델 서버로 보낸다.
출력에 한 번 찍힌 값은 대화 컨텍스트와 로컬 세션 기록에 남고, 사후에 가려도 회수되지 않는다.
→ 값이 노출되면 교체해야 하고, 보안 담당 보고 대상이 될 수 있다.

## 대상

토큰, API 키, JWT/서명 키, 비밀번호, 클라이언트 시크릿, 개인 키, 내부 연동 계정 정보.
설정 파일(`application-*.yml`, `.env*`)과 키/인증서 파일(`*.pem`, `*.p12`, `*.pk8`)에 주로 있다.

## 규칙

- 비밀값 점검은 **값이 출력되지 않게** 한다. 쓰는 것: 줄 번호, 키 이름, "환경변수 참조(`${...}`)인가" 여부,
  값의 해시 앞 몇 자리(환경 간 동일 값 여부 비교용).
- 값이 나오는 `cat`, `sed`, `cut`, `grep` 패턴, 설정 파일 통째 Read 는 쓰지 않는다.
  필요하면 비밀 키 줄을 뺀 줄 범위만 읽는다.
- 값을 꼭 봐야 하면 **먼저 사용자에게 알리고 허락**을 받는다.
- 답변, 보고서, 메모리, 커밋 메시지, 파일에도 값을 쓰지 않는다 (파일 경로·줄 번호·종류만).
- 실수로 출력됐으면 숨기려 하지 말고 바로 사용자에게 알린다. 교체 대상(파일·줄·종류)을 값 없이 정리해 보안 담당에게 넘긴다.

## 강제 수단 (규칙만으로는 사람·AI 실수를 못 막는다)

- 도구의 deny 권한으로 위 경로의 읽기를 막는다 (Claude Code: `settings.json` 의 `permissions.deny` 에 `Read(...)`).
  Bash 의 `cat`/`grep` 은 패턴으로 완전히 못 막으므로 위 규칙과 같이 쓴다.
- 근본 해결은 설정 파일에서 값을 빼고 환경변수·Secret Manager 참조로 바꾸는 것이다.
  그러면 파일을 읽어도 값이 없다.

관련: `no-sensitive-in-files.md` (파일에 남기지 말 것 — 이 규칙은 도구 **출력**에 대한 것).
앱 저장소에 더 긴 규정이 있으면 그쪽이 우선한다.
