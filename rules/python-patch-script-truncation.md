# 파이썬 패치 스크립트의 `open(f,'w')`는 파일을 먼저 비운다

인플레이스 치환 스크립트를 `io.open(f,'w').write(s)` 한 줄로 쓰면, 인자 평가 중에
예외가 나도 파일은 이미 잘려 있다. 실제로 143KB 소스 파일이 0바이트가 된 사례가 있다
(2026-10-12, 몽글놀이 build16 `web/worlds/world-ui.js`, 복구에 왕복 여러 번 소요).

- 패치 스크립트는 **먼저 문자열을 완성하고**, 그다음에 열어 쓴다:
  `data = s.replace(...)` → `io.open(f,'w',...).write(data)`.
  더 안전하게는 임시 파일에 쓰고 `os.replace`로 갈아끼운다.
- 수정 대상이 버전 관리되지 않는 트리(압축 해제한 납품 소스 등)라면, 작업 시작 시
  원본 사본을 따로 두고 그 사본으로 복구할 수 있는지 먼저 확인한다.

## 함께 걸린 함정: 도구 입력의 `\u` 이스케이프

Bash/Write 도구 인자는 JSON으로 전달되므로 `\\uD800`처럼 적어도 `\uD800`으로
접혀서 파일에 들어간다. 자바스크립트 정규식에 `\uD800-\uDBFF` 같은 범위를 쓰려 하면
파이썬 문자열에 실제 서러게이트가 들어가 `UnicodeEncodeError`로 터진다(위 사고의 원인).

- 생성할 코드에 `\u` 이스케이프가 필요하면, 이스케이프 없이 표현한다
  (`charCodeAt` 비교, `String.fromCharCode`, 또는 해당 문자 자체를 넣기).
