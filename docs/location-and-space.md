# 위치·공간 변화에도 AI가 같은 기준으로 일하게

팀 harness와 앱을 쓰는 사람·AI용이다.  
**위치** = 망·사이트·머신·타임존이 어디인지.  
**공간** = 어느 기기·어느 세션·누가 그 자리를 이어받는지.

목표는 대화창이 바뀌거나 자리를 옮겨도, **파일에 남은 팀 기준**으로 같은 일을 이어가는 것이다.


## 용어

| 말 | 뜻 | 예 |
|----|-----|-----|
| 위치 | 어디서 일하는지 | 사내망, 재택, VPN, 새 노트북, 다른 타임존 |
| 공간 | 어떤 자리·세션에서 이어가는지 | 책상 PC, 노트북 뚜껑, 새 채팅 창, 구현→검수 교대 |
| 살아남는 것 | 창을 닫아도 남음 | Git 코드, 이 harness, 앱 `AGENTS.md`, progress-log, 핸드오프 |
| 사라지는 것 | 세션이 끝나면 없음 | 그 창의 대화, 로컬만의 임시 메모 |


## 1. 새 PC·머신 위치가 바뀔 때

1. 앱과 harness를 clone 한다. 예: 앱 `C:\mid\mid`, harness 형제 `C:\mid\harness-history`.
2. 앱 `AGENTS.md`의 harness 경로·원격 URL을 확인한다. 경로가 다르면 사용자에게 한 번 묻는다.
3. harness에서 `git pull` 후 `README.md`, `rules/`, 필요 `skills/`를 읽는다.
4. Grok이면 `docs/connect-grok.md`대로 `[skills] paths`를 **이 머신에** 넣는다.
5. Claude / Codex는 `docs/connect-agents.md`대로 절대경로로 직접 읽는다.
6. MCP·토큰 등 시크릿은 레포에 없다. 키 **이름**은 `docs/mcp.team.example.toml`을 보고, 값은 이 머신에서만 설정한다.
7. clone이 없거나 pull이 실패하면 코딩을 시작하지 않는다 (`skills/session-start-check`).

**완료:** 팀 스킬·규칙이 보이고, 앱 AGENTS·활성 progress-log를 읽은 뒤 슬라이스를 시작할 수 있다.


## 2. 망·사이트 위치가 바뀔 때

팀마다 표만 채운다. 아래는 칸 예시이다.

| 위치 | 해도 됨 | 하면 안 됨 |
|------|---------|------------|
| 사내망 | clone, pull, 로컬 빌드·테스트, (정책에 따라) 배포 | 정책을 어기는 외부로 코드·키 반출 |
| 재택 / 일반 인터넷 | clone, pull, 문서·슬라이스 작업 | 사내망 전용 DB·프로덕션 접근(VPN 없이) |
| 고객사·제한 VPN | 해당 VPN 범위의 작업만 | VPN 밖 기기에 고객 시크릿 저장 |

에이전트에게:

- 현재 망을 모르면 사용자에게 한 번 묻는다. 추측으로 배포·프로덕션을 건드리지 않는다.
- “실행은 사내에서만, 프롬프트는 어디서든” 같은 분리가 있으면 앱/인프라 문서를 따른다.
- 이 harness에는 망 비밀번호·VPN 설정을 넣지 않는다.


## 3. 타임존·비동기로 위치가 갈릴 때

다음 사람·AI가 **대화 원문 없이** 이어갈 수 있게 남긴다.

인수인계에 넣을 최소 항목:

- 지금 슬라이스 목표·완료 조건
- `건드릴 파일` 목록
- 이미 한 결정 / 보류 / 오탐
- 막힌 것·다음에 할 한 가지
- 작성자 접두 `[Grok|Claude|Codex|담당-라벨] YYYY-MM-DD:`

앱 progress-log·핸드오프에 쓰고, 대화·잔여%·실명은 쓰지 않는다 (`rules/no-sensitive-in-files.md`).

같은 실수가 반복되면 `skills/promote-learning`으로 harness에 올려, 시간이 지나도 같은 기준이 남게 한다.


## 4. 기기 공간 — 책상 · 노트북 · 회의실

| 상황 | 할 일 |
|------|--------|
| 자리를 뜨거나 뚜껑을 닫기 전 | progress-log 또는 핸드오프에 “어디까지 / 다음에 무엇을” 한 절 |
| 실행이 **내 노트북에만** 있을 때 | 창을 닫으면 작업도 멈춘다고 가정. 반드시 파일에 남긴 뒤 이동 |
| 실행이 **공용·원격 워크스페이스**에 있을 때 (팀이 쓸 때만) | 재접속 방법·권한만 확인하고, 시크릿은 공용 자리에 두지 않음 |
| 폰·태블릿 | 구현하지 않는다. 상태 확인·검수 메모 정도만 (팀이 허용할 때) |

개인 토큰·`.env`를 공용 모니터 PC에 남겨 두지 않는다.


## 5. 세션 공간 — 채팅 창·도구가 바뀔 때

새 세션·다른 도구(Grok↔Claude↔Codex)로 갈아탈 때:

1. `skills/session-start-check` 수행 (harness pull, rules 직접 읽기, progress-log)
2. 진실은 파일이고 이전 창의 대화가 아니다
3. 앱 규칙과 harness가 겹치면 **앱 `AGENTS.md` 우선**
4. 팀 공통 절차를 고칠 때는 이 harness에만 쓰고, 앱 커밋과 섞지 않는다

프롬프트: `README.md`의 «공통» + 도구별 절. 경로 자리표시 `<HARNESS>` · `<APP>`.


## 6. 담당 공간 — 누가 그 자리를 이어받는지

- 핸드오프의 `건드릴 파일` 밖은 수정하지 않는다
- 검수는 `통과|부분통과|반려` + 수정 목록만 (`skills/slice-review-checklist`)
- 구현과 검수가 같은 파일을 동시에 크게 고치지 않는다
- harness 변경은 리뷰 후 merge. 건드릴 파일에 harness 경로가 없고 승격 지시가 없으면 harness를 편집하지 않는다


## 7. catchup 템플릿 (복붙용)

```text
[작성자] YYYY-MM-DD: catchup
- 목표:
- 건드릴 파일:
- 한 것:
- 결정 / 보류:
- 막힌 것:
- 다음 한 가지:
- 읽어야 할 로그/문서:
```

민감정보·프롬프트 원문·잔여%는 넣지 않는다.


## 8. 하지 않음

- 시크릿·실명·대화 원문을 Git(harness·앱)에 넣기
- pull 실패·clone 없음인데 코딩 강행
- 망·사이트를 추측해 배포·프로덕션 조작
- 검토 없이 팀 스킬/규칙을 전 원에 강제 전파
- “CLAUDE.md 없음 = 규칙 없음”으로 해석 (앱 정본은 `AGENTS.md`)
