# 3자 리뷰는 서로 다른 걸 잡고, 결론이 충돌하면 직접 재현해야 한다

- Date: 2026-09-19
- From: risk-alert-bot 코드리뷰 세션 (Claude·Codex·Grok 동시 실행)
- Status: candidate

## Fact / decision

같은 변경분을 같은 프롬프트로 Claude(도구 사용 가능한 fork)·Codex·Grok 에 동시에 돌렸다.
지적이 겹치는 부분보다 **각자만 잡아낸 것이 더 많았다.**

관측된 경향:

- **Claude**(파일 읽기·실행 가능): 실제로 코드를 돌려 재현하는 상호작용 버그. 라이브 상태를
  건드리지 말라고 프롬프트에 명시해야 안전하다.
- **Codex**: 데이터를 직접 세어 수치로 반박하는 지적(“이 조건이면 256건이 어긋난다”), 설계
  수준 결함(수신자 선정 오류 등).
- **Grok**: 문자열·경계 조건, 접근성·보안 구멍(`"중구"` 를 `"중"` 으로 잘라 비교하는 버그 등).

**중요: 두 리뷰어의 결론이 정면으로 충돌했다.** 한 변경(중복 판정에서 `related_update` 를
발송하지 않도록 바꾼 것)에 대해 Claude 는 "안전하다 — 격상은 여전히 통과한다"고 했고,
Codex 는 "별개 사건까지 누락시킨다"며 재현 사례를 제시했다. 직접 재현해 보니 **Codex 가
맞았다** (다른 구·다른 날 화재가 한 사건으로 묶여 뒤엣것이 통째로 버려짐).

## Repro / when it matters

- 리뷰 결과를 그대로 반영하기 전에, **최소한 "심각" 등급 지적과 리뷰어 간 충돌 지점은 직접
  재현**한다. 세 리뷰어 모두 틀린 지적을 섞어서 낸다.
- 반대로, 리뷰어가 "안전하다"고 한 것도 근거 없이 믿지 않는다 — 위 사례에서 안전 판정이
  틀렸다.
- 호출 방법(이 머신 기준): `codex exec --skip-git-repo-check "<프롬프트>"`,
  `grok -p "<프롬프트>"`. 긴 프롬프트는 파일에 써 두고 `"$(cat ...)"` 로 넘긴다.
  Grok 헤드리스가 조용히 끊기는 건은 `rules/grok-headless-review-caveat.md` 참고.

## Do not promote if

리뷰어별 "경향"은 표본 1회짜리 인상이라 규칙으로 굳히기엔 이르다.
다만 **"충돌하면 직접 재현한다"** 는 부분은 도구와 무관하게 유효하므로, 반복 관측되면
`rules/` 또는 `skills/slice-review-checklist` 에 병합 검토.
